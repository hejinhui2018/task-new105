# SignFlow 签署流程验收台

用 React + TypeScript + Vite 从零搭建的法务签署流程演练台。在浏览器里模拟一份文件由
**员工 → 主管 → 外部合作方**依次签署的全过程，重点解决一个真实痛点：

> 文件补页或签署顺序变化后，旧签名不应继续显示"有效"，直到最后提交才暴露整份文件要重签。

本台的做法是：**每个决定都绑定当时的文件指纹与前序状态哈希**，补页即时换指纹、旧签名即时失效；
晚到回执、重复签署、版本替换在到达时逐条校验，并在审计台账中给出可解释的拒收原因。

## 启动

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 命令行运行 5 个验收场景 / 30 条断言
npm run test:ui    # jsdom 真实 React DOM 交互冒烟（签署/补页/撤销重做/刷新恢复/页面内断言）
npm run build      # 类型检查 + 生产构建
```

## 核心模型

### 文件指纹（`src/lib/hash.ts`）

- 每个版本的指纹 = FNV-1a(`DOC|v{n}|全部页标签`)，任何一页增改都会得到新指纹。
- 补页（AMEND）产生新版本与新指纹，保留父指纹形成版本谱系。

### 签署轮次与哈希链（`src/lib/engine.ts`）

- 发起（START）把"文件指纹 + 角色顺序"压成**创世锚点**。
- 每一枚有效签名的 `prevHash` 指向前一枚链上决定（START→员工→主管→合作方），
  签名同时锁定 `signedFingerprint`、`signedPrevHash` 与身份确认快照。
- 查看 / 发送类回执**留痕但不推进签名链**，避免"看过文件"这种事实性动作阻断后续签署。
- 被拒收的回执同样入账（REJECTED），但不改变链头。

### 异步回执与到达时校验（关键）

点击"查看/签署/拒绝"不会立即生效，而是生成一份**在发出时就锁定指纹与前序哈希**的回执
（`PendingMessage`），经过可调传输延迟后在时钟步到达。到达时按固定优先级校验：

| 优先级 | 原因码 | 含义 |
| --- | --- | --- |
| 1 | `STALE_FINGERPRINT` | 回执指纹 ≠ 当前文件指纹（文件已补页/换版） |
| 2 | `EXPIRED` | 链接 90 分钟有效期已过（按**到达时刻**判定） |
| 3 | `RUN_INACTIVE` | 轮次已拒绝/撤回/被新版本取代，晚到回执不入链 |
| 4 | `ALREADY_SIGNED` | 该槽位已有有效签名（重复重传） |
| 5 | `SLOT_TERMINAL` | 槽位已拒绝/撤回/失效 |
| 6 | `NOT_IDENTIFIED` | 签署时身份确认快照为"否" |
| 7 | `PREV_NOT_SIGNED` | 前序角色尚无有效签名（越序签署） |
| 8 | `HASH_MISMATCH` | 回执锁定的前序哈希 ≠ 当前链头（发出后链上又有决定 / 被篡改） |

丢包回执在"应到时刻"登记 `LOST_IN_TRANSIT`，台账可见但服务端状态不变。

## 功能清单

- **单步 / 自动播放 / 暂停**：虚拟时钟每步 10 分钟，自动播放 1.2 秒一步，轮次终止自动暂停。
- **发送、查看、签署、拒绝、撤回、重新发起**：拒绝需填理由；撤回保留已完成签名留痕。
- **补页换版**：进行中的旧签名即时变 `invalidated`，未签署链接作废，需基于新指纹重发整轮。
- **故障注入**：下一回执丢包 / 重复重传 / 前序哈希篡改 / 延迟 30 分钟；可调基础延迟；
  可对任意角色手动"重放查看/签署"模拟晚到回执。
- **撤销 / 重做**：200 步快照栈（Ctrl/⌘+Z、Ctrl/⌘+Shift+Z）。
- **刷新恢复**：状态含撤销栈整体持久化到 localStorage，刷新后现场无损恢复。
- **重置**：清空存档恢复初始文件。
- **审计台账**：每个决定（含拒收）显示时刻、动作、角色、绑定的 FP/prev/hash、入链状态与判定依据。

## 验收场景（右栏一键运行，`npm test` 同构）

1. **顺序签署**：三轮按序入链；流程完成后重放旧回执 → `RUN_INACTIVE`。
2. **补页换版**：员工、主管签完后补页 → 旧签名即时失效、合作方迟到回执 → `STALE_FINGERPRINT`，
   基于 v2 重新发起并整轮重签成功。
3. **发起方撤回**：员工签完后撤回 → 主管链接作废、晚到回执拒收、签名留痕，可重新发起。
4. **链接过期**：主管 90 分钟未操作 → 系统关闭轮次，过期后的回执不能"复活"流程。
5. **重复 / 晚到 / 越序 / 篡改**：一次覆盖 `PREV_NOT_SIGNED`、`ALREADY_SIGNED`、
   `HASH_MISMATCH`，以及"晚到 30 分钟但链未变 → 仍有效"的对照。

场景在隔离状态中运行断言，不影响画布；也可把最终态载入画布逐条检视台账。

## 目录

```
src/
  types.ts                  领域类型
  lib/
    hash.ts                 FNV-1a 指纹与决定哈希
    engine.ts               纯函数 reducer：轮次、槽位、回执校验、过期、补页失效
    reason.ts               原因码的法务可读解释
    scenarios.ts            5 个验收场景脚本与断言
    useFlowStore.ts         撤销重做 / localStorage 恢复 / 自动播放
    statusMeta.ts           状态与动作的展示元数据
  components/               顶栏、文件、角色身份、签署链、队列、台账、故障、场景面板
```

引擎层是纯 TypeScript（无 React 依赖），同一套 reducer 同时驱动 UI 与命令行断言，
保证"演练所见"与"验收所测"完全一致。
